# โหมด 3 มิติด้วย three.js — ก้อนควันแบบ raymarch

วันที่ 2026-09-14 · สเปกต้นทาง: คำขอของเจ้าของงาน "อยากได้ 3D แบบ nukesimulation.com"

เอกสารนี้คุมการเพิ่ม **ตัววาดโหมด 3 มิติตัวที่สอง** ที่ใช้ three.js
ตัวเดิม (MapLibre + `fill-extrusion`) **ยังอยู่ครบ ไม่แตะ ไม่ลบ** — กลายเป็น legacy

## การตัดสินใจของเจ้าของงาน (2026-09-14)

1. **ฉากท้องถิ่น ENU ไม่ใช่โลกทั้งใบ** — ระนาบเมตรรอบกองไฟ กว้างเท่ารัศมี `R` ของกริด
   พิกัด `x, y` ในฉากคือพิกัดเอนจินเป๊ะ ไม่มีการแปลง ไม่มี ECEF
   (แลกกับว่าถ้าวันหลังอยากต่อ Google Photorealistic 3D Tiles ต้องเพิ่มชั้นแปลง ECEF→ENU)
2. **ความหนาแนวดิ่งยัง "สร้างขึ้น" เหมือนเดิม ไม่แก้ `packages/engine`**
   เอนจินคืนความเข้มข้น**ระดับพื้น**เท่านั้น แนวราบคือของจริง แนวดิ่งคือการประมาณ
   ข้อจำกัดข้อนี้ไม่ได้หายไปจากการเปลี่ยนตัววาด ต้องป้ายกำกับต่อ
3. **ก้อนควันวาดด้วย `Data3DTexture` + raymarch** ไม่ใช่ sprite ไม่ใช่ระนาบซ้อนชั้น
4. **MapLibre เก็บเป็น legacy ถาวร** — สวิตช์เลือกตัววาดเป็นของถาวร ไม่ใช่ของชั่วคราว
   ค่าตั้งต้นคือ three.js
5. **เพิ่ม `three` เป็น dependency ของ `app`** pin เวอร์ชันเป๊ะ `0.186.0` ตามธรรมเนียม repo
   (d3 `7.9.0`, leaflet `1.9.4`, maplibre-gl `4.7.1` ล้วน pin เป๊ะ)
6. **ยังไม่ทำตึก photorealistic** — Google 3D Tiles มีค่าใช้จ่าย และแถบแม่ฮ่องสอน
   ซึ่งเป็นเคสหลักของโปรเจกต์ไม่มีข้อมูลตึกอยู่ดี บันทึกไว้ใน §11

## ทำไมไม่ใช่แค่ "เปลี่ยนให้สวยขึ้น"

`fill-extrusion` ของ MapLibre วาดก้อนควันเป็น**กล่องสี่เหลี่ยมต่อกัน** ทำให้เสียสองอย่าง
ที่เป็นเนื้อหาของโปรเจกต์ ไม่ใช่แค่ความสวย:

- **ภูเขาบังควันไม่ได้** กล่องเป็นทรงตัน วาดทับภูมิประเทศเสมอ ทั้งที่ทั้งโปรเจกต์
  สร้างมาเพื่อตอบว่า "ภูเขาเบนลมหรือลมข้ามไป" — raymarch หยุดรังสีที่ผิวดินได้จริง
- **ความเข้มข้นอ่านเป็นชั้นบันได** กล่องหนึ่งใบมีสีเดียว ทั้งที่ค่าจริงไล่ต่อเนื่อง
  raymarch สะสมค่าตามทางเดินของรังสี จึงตรงกับความหมายของ "ความเข้มข้นสะสมที่ตาเห็น"

## โมดูลใหม่และรอยต่อ

```
app/src/map3d/three/
  index.js          facade ที่ app.js คุยด้วยตัวเดียว — create / update / resize / fitBounds / dispose
  scene.js          renderer · camera · OrbitControls · ฟ้า · หมอก · แสงอาทิตย์ · loop
  terrain.js        PlaneGeometry จาก elev ของ services/dem.js + normal (เงาเขามาจากแสงจริง)
  basemap.js        โมเสกภาพดาวเทียม Esri → CanvasTexture (ใช้ tile helper ของ dem-math.js ซ้ำ)
  volume-field.js   ★ บริสุทธิ์ ทดสอบใน node — grid2D + hour → Float32Array Nx·Ny·Nz + meta
  volume-mesh.js    Data3DTexture (half-float) + ShaderMaterial + กล่องครอบโดเมน
  volume.glsl.js    vertex / fragment shader เป็นสตริง แยกไฟล์ให้อ่านออก
  drape.js          ปูรูปหลายเหลี่ยม/ภาพให้เลาะผิวภูมิประเทศ (ใช้กับแปลงเผาและภาพ 2D ทาบพื้น)
  markers.js        แปลงเผา + ตัวรับ
```

ของเดิมที่ **ไม่แตะเนื้อในแม้แต่บรรทัดเดียว**: `app/src/map3d/volume.js` ทั้งไฟล์
(ของใหม่ **import** `sigmas()` กับ `downsampleMax()` จากไฟล์นี้ — import ไม่ใช่การแก้)
และบล็อก MapLibre ใน `app.js`: `init3D` `await3D` `plumeVolume` `plotsGeo` `recsGeo` `diag`

**ข้อยกเว้นเดียว** คือ `skyFor()` ใน `app.js` ต้องย้ายออกมาเป็น `app/src/map3d/sky-palette.js`
แล้วให้ทั้งสองตัววาด import — **ย้ายที่ ไม่แก้เนื้อใน** ตัว MapLibre เรียกผ่าน import แทน
เหตุผล: ถ้า copy จานสีไปไว้ฝั่ง three สองโหมดจะเปลี่ยนสีฟ้าไม่พร้อมกันเมื่อมีคนแก้ทีหลัง

### `volume-field.js` — ส่วนที่ต้องซื่อสัตย์ที่สุด

```js
buildField({ grid, res, hour, step, Nz }) →
  { data: Float32Array(Nx*Ny*Nz), Nx, Ny, Nz, zTop, vmax }
```

เรียงแบบ `k*Nx*Ny + j*Nx + i` (z ช้าสุด) ตามที่ `Data3DTexture` ต้องการ

**สูตร** สำหรับคอลัมน์ `(i, j)` ที่มีค่าพื้น `C₀ = grid2D[i][j]`

```
field(i, j, k) = C₀ · vert(z_k) / vert(0)
vert(z)        = exp(−(z−H)² / 2σz²) + exp(−(z+H)² / 2σz²)
```

- **หาร `vert(0)`** ทำให้ชั้น `z = 0` เท่ากับค่าที่เอนจินคำนวณ**เป๊ะ** ไม่ใช่ใกล้เคียง
  นี่คือสิ่งเดียวที่ทำให้พูดได้ว่า "สิ่งที่เห็นที่พื้นคือผลการคำนวณ"
  ค่าเหนือพื้นคือการกระจายที่**สมมติ** ไม่ใช่ผลการคำนวณ
- **กับดักของการหาร `vert(0)` — ต้องรู้ตัวก่อนเขียน** เมื่อพลูมลอยสูง (`H` มาก `σz` แคบ)
  `vert(0)` เข้าใกล้ 0 อัตราส่วนจึงระเบิด และที่แย่กว่าคือถ้ากริดพื้นเป็น 0 พอดี
  ทั้งคอลัมน์จะเป็น 0 **ทั้งที่ของจริงมีควันลอยอยู่ข้างบน**
  กติกา: จำกัด `vert(z)/vert(0) ≤ 1e4` และบันทึกเป็นข้อจำกัดข้อ 6 ใน §11
  ยอมข้อนี้เพราะทางเลือกคือคำนวณค่าบนอากาศจากสูตร Gaussian ใหม่ ซึ่งจะทิ้ง
  รูปร่างแนวราบที่เอนจินคำนวณจริง (รวมการเบนตามภูมิประเทศ) — ของที่สำคัญกว่า
- `+exp(−(z+H)²/2σz²)` คือ**เงาสะท้อนที่พื้น** — ควันชนพื้นแล้วสะท้อนกลับขึ้น
  เป็นเทอมมาตรฐานของ Gaussian plume ตัวเดียวกับที่ `packages/engine/src/gaussian.ts` ใช้
- `H` = ความสูงพลูม ใช้ `hour.Hsm` ถ้า `hour.qSm > 0` ไม่งั้น `hour.Hfl`
  (เหมือน `volume.js` เดิม — เฟสคุกรุ่นเป็นตัวกำหนดค่าที่พื้น)
- `σz` = `sigmas(x, hour.stab)[1]` โดย `x` คือ**ระยะท้ายลมของคอลัมน์นั้น** ไม่ใช่ค่าเดียวทั้งกริด
  ยืมฟังก์ชัน `sigmas()` จาก `map3d/volume.js` ตรงๆ (import ไม่ใช่ copy) เพื่อกัน
  สูตรสองชุดหลุดจากกัน — ของเดิมเคยพลาดแบบนี้มาแล้ว (ดูคอมเมนต์หัวไฟล์ `volume.js`)
- **เพดานชั้นผสม** `z > max(hour.mix, 60)` → 0 ตัดแข็ง ควันไม่ทะลุชั้นผสม
- `zTop = min(max(mix,60), H + 3σz̄)` ปัดขึ้นให้สวย · `Nz` ตั้งต้น 48

**ความละเอียด** ย่อแนวราบด้วย `downsampleMax` ของเดิม (ค่าสูงสุดในบล็อก ไม่ใช่ค่าเฉลี่ย —
เหตุผลอยู่ในคอมเมนต์ `volume.js` แกนพลูมที่แคบกว่าบล็อกจะถูกเฉลี่ยจนจาง) ให้ได้ราว
`Nx = Ny = 96` → `96·96·48` = 442,368 voxel × 2 ไบต์ = **865 KB ต่อชั่วโมง** สร้างใหม่เมื่อเปลี่ยนชั่วโมง
ไม่ถือทั้ง 24 ชั่วโมงพร้อมกัน

### `volume-mesh.js` + `volume.glsl.js`

- `Data3DTexture` · `RedFormat` · `HalfFloatType` · `LinearFilter` · `ClampToEdgeWrapping`
  half-float ตัดปัญหาการเข้ารหัสทิ้ง ถ้า `WebGL2` ใช้ไม่ได้ให้ขึ้นข้อความบอกตรงๆ แล้วแนะให้กด legacy
- กล่องครอบ `BoxGeometry(2R, 2R, zTop)` · `side: BackSide` · `depthWrite: false` · `transparent: true`
  วาดหลังภูมิประเทศเสมอ
- **กล่องต้องวางที่ `(cx, cy)` ไม่ใช่ที่กองไฟ** — ศูนย์กลางกริดของเอนจินเลื่อนไปทางท้ายลม
  (ดู `GridSpec` ใน `packages/engine/src/types.ts`) วางผิดแล้วควันจะเหลื่อมจากกริดทั้งก้อน
- **ตัดรังสีด้วยผิวดินโดยตรง ไม่ต้องทำ depth prepass** — เรามี DEM เป็น texture อยู่แล้ว
  shader สุ่ม `elevTex` ที่ `(x, y)` ของจุดบนรังสี ถ้า `z < elev` ให้หยุด
  วิธีนี้ถูกต้องพอดีกับเคสเรา (ภูมิประเทศเป็น heightfield ไม่มีอะไรยื่นเกิน)
  และเลี่ยง render target + `DepthTexture` ทั้งชุด
- เดินรังสี: slab method หาช่วงตัดกล่อง → เดิน 64–128 ก้าว → สะสมหน้าไปหลัง
  `α = 1 − exp(−k · c · dt)` (Beer–Lambert) โดย `k` ผูกกับสไลเดอร์ `#smokeopa`
- **จุดเริ่มแบบสุ่ม (jitter)** ด้วย hash ของพิกัดจอ ไม่งั้นจะเห็นวงแหวนเป็นชั้นๆ ชัดมาก
- **สีต้องตรงกับ 2D** สร้าง LUT 1 มิติจาก `BANDS` ชุดเดียวกับที่แผนที่ 2D ใช้
  ห้ามคิดสีใหม่ในโหมด 3D เด็ดขาด ไม่งั้นคนอ่านค่าจากสองหน้าจอแล้วได้คนละคำตอบ
- `#pexag` (ตัวคูณความหนา) คูณที่ `σz` ตอนสร้าง field — **เพื่อการมองเห็นเท่านั้น**
  เหมือนของเดิม และต้องมีป้ายบอกว่ายกแล้ว

### `terrain.js`

- `PlaneGeometry(2R, 2R, N−1, N−1)` ยกแต่ละจุดด้วย `elev[j*N+i] × exag` จาก `services/dem.js`
  (มีอยู่แล้ว คืน `Float32Array N×N` เรียงตรงกับกริดเอนจิน — ไม่ต้องเขียนตัวดึงใหม่)
- `computeVertexNormals()` แล้วใช้ `MeshStandardMaterial` + `DirectionalLight`
  **เงาเขามาจากแสงจริง ไม่ใช่ hillshade คำนวณทับ** — ดีกว่าของเดิมเชิงหลักการ
  เพราะทิศแสงเปลี่ยนตามเวลาในวันได้จริง
- ไม่มี DEM → ระนาบราบ + ป้ายบอก เหมือนกติกา fail-safe เดิม ห้ามพังทั้งแอป

### `basemap.js`

- ภาพดาวเทียม Esri World Imagery (URL เดียวกับที่ `app.js` ใช้อยู่)
- ใช้ `chooseZoom` / `tileRange` / `boundsAround` จาก `services/dem-math.js` ซ้ำ
  แต่**งบไทล์คนละตัวกับ DEM** — DEM จำกัด 3×3 พอ เพราะ SRTM 30 ม. ละเอียดกว่านั้นไม่มีจริง
  ส่วนภาพต้องการความคมกว่ามาก ตั้งงบ 6×6 ที่ z สูงสุดเท่าที่ยังไม่เกิน
- `img.crossOrigin = 'anonymous'` **บังคับ** — WebGL อัป texture จาก canvas ที่ปนเปื้อนไม่ได้
  (ต่างจาก `<img>` ธรรมดาที่ไม่สน) Esri รองรับ CORS อยู่แล้ว
- โหลดไม่ได้ → พื้นสีเรียบ + ป้ายบอก ไม่พังทั้งแอป

### `scene.js`

- `WebGLRenderer({ antialias: true })` · `OrbitControls` หมุนรอบจุดกองไฟ
- กล้องเริ่มที่มุมต่ำและใกล้พื้น เหมือนเหตุผลของ MapLibre เดิม (`pitch: 74`) —
  มุมสูงทำให้ภูเขาดูแบน
- ฟ้าและหมอกใช้จานสีจาก `skyFor(hourKey)` **ตัวเดิมใน `app.js`** ย้ายมาเป็น export ร่วม
  ไม่ copy — เพื่อให้สองตัววาดเปลี่ยนสีพร้อมกันเสมอ
- ทิศและมุมอาทิตย์คำนวณจากชั่วโมงและละติจูด → ตำแหน่ง `DirectionalLight`
- ห่วง render หยุดเมื่อสลับกลับ 2D (`cancelAnimationFrame`) ไม่กินซีพียูค้าง

### `index.js` — facade

```js
export async function create3D(container, view) → handle
handle.update(view)
handle.resize()
handle.fitBounds(bbox)
handle.dispose()
```

`view` เป็น**ก้อนข้อมูลธรรมดา** ไม่ใช่ `S` ทั้งก้อน เพื่อให้ทดสอบและอ่านง่าย:

```
{ origin, result, hourIndex, elev, bands, bandOf, bg, toLL,
  opts: { exag, pexag, smokeOpacity, showGroundLayer },
  plots, receptors, groundRaster }
```

## จุดที่แตะ `app.js` (ตั้งใจให้เล็กมาก)

- state ใหม่ `S.renderer3 = 'three' | 'maplibre'` (จำใน localStorage)
- `set3D(on)` แตกสองทาง — ทางเดิมคงเดิมทุกบรรทัด
- `update3D()` เพิ่ม early-return ไปเรียก facade เมื่อโหมดเป็น three
- `resize` / `fitBounds` เพิ่มสาขา
- `skyFor()` ย้ายออกไป `map3d/sky-palette.js` แล้ว import กลับเข้ามา (เนื้อในเหมือนเดิมทุกบรรทัด)
- สวิตช์ตัววาดบนสุดของ `#d3bar`

## ข้อจำกัดที่ต้องเขียนลง README และขึ้นบนหน้าจอ

1. **ความหนาแนวดิ่งไม่ใช่ผลการคำนวณ** เอนจินคืนค่าระดับพื้นเท่านั้น
   สิ่งที่เห็นเหนือพื้นคือการกระจาย Gaussian ที่สมมติจาก `H` และ `σz` ของชั่วโมงนั้น
   **ค่าที่ผิวดินเท่านั้นที่เป็นของจริง** — ข้อนี้มีอยู่แล้วใน `volume.js` และไม่หายไป
2. `#pexag` ยกความหนาเพื่อการมองเห็น ไม่กระทบตัวเลขใดๆ
3. ภาพดาวเทียมเป็นภาพถ่ายเก่า ไม่ใช่สภาพ ณ วันที่จำลอง
4. ไม่มีตึกจริง — ยังไม่ได้ต่อ Google Photorealistic 3D Tiles และแถบแม่ฮ่องสอน
   ซึ่งเป็นเคสหลักก็ไม่มีข้อมูลตึกของ Google อยู่แล้ว
5. raymarch กินการ์ดจอ เครื่องเก่าอาจหืด — มีปุ่มกลับไป legacy เสมอ
6. **พลูมที่ลอยสูงจนไม่แตะพื้นจะมองไม่เห็นในโหมด 3 มิติ** เพราะความหนาแนวดิ่งสร้างจาก
   ค่าที่พื้น ถ้าค่าที่พื้นเป็นศูนย์ทั้งคอลัมน์ก็เป็นศูนย์ — เกิดได้ตอนอากาศเสถียรมาก
   และควันลอยค้างเหนือชั้นผกผัน **ตัวเลขในตารางยังถูกต้อง ภาพต่างหากที่บอกไม่ครบ**
   ข้อนี้เป็นผลโดยตรงของการตัดสินใจข้อ 2 ใน §การตัดสินใจของเจ้าของงาน

## ความเสี่ยงที่รู้ตัวไว้ก่อน

- **fill-rate** ตอนกล้องจ่อเข้าไปในก้อนควัน จำนวนก้าวคงที่จะช้าลงฮวบ
  แก้ด้วยลดจำนวนก้าวตามระยะ และลดความละเอียดการวาดเมื่อเฟรมตก
- **แถบวงแหวน (banding)** ถ้าลืม jitter จะเห็นชัดมาก ต้องมีตั้งแต่แรก
- **`Data3DTexture` ต้องการ WebGL2** เครื่องเก่ามาก ๆ ตก → ตรวจแล้วบอกตรงๆ พร้อมชี้ไป legacy
- **สองตัววาดหลุดจากกัน** ถ้า `sigmas()` หรือ `BANDS` ถูก copy แทน import
  กติกาคือ import เท่านั้น ห้าม copy
